## 1. Что это за продукт

PitchZone — платформа для организации и проведения турниров по киберфутболу (EA FC, eFootball и т.п.), где игроки и команды платят взнос за участие, а платформа удерживает комиссию с призового фонда. Деньги участников хранятся в эскроу до завершения турнира и автоматически распределяются победителям.

## 2. Роли пользователей

| Роль                     | Права                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Guest**                | просмотр публичных турниров и статистики без регистрации                                               |
| **Player**               | регистрируется, вступает в турниры/команды, играет матчи, имеет кошелёк                                |
| **Team Captain**         | управляет составом команды, регистрирует команду на турниры                                            |
| **Organizer (verified)** | создаёт публичные турниры с реальными призовыми, проходит верификацию (KYC/подтверждение через админа) |
| **Moderator**            | разбирает споры (disputes), банит читеров, модерирует контент                                          |
| **Admin**                | полный доступ: финансы, настройка комиссий, управление ролями, аналитика                               |

## 4. Полные пользовательские сценарии

### 4.1 Регистрация и профиль

1. Пользователь регистрируется через email/пароль либо OAuth (Discord, Steam).
2. Заполняет никнейм, страну, аватар.
3. Стартовый Elo-рейтинг = 1000.
4. Профиль публично показывает: рейтинг, историю матчей (W/L), текущие турниры, достижения (значки за призовые места).

### 4.2 Создание команды

1. Игрок создаёт команду → становится капитаном.
2. Капитан приглашает других игроков по нику/ссылке.
3. Приглашённый подтверждает вступление.
4. Командный Elo = среднее/агрегат рейтингов участников (пересчитывается после каждого матча).

### 4.3 Создание турнира (мастер из 5 шагов — уже подробно описан ранее)

**Шаг 1 — Основное**: название, описание, баннер, игра, дата старта, дедлайн регистрации.

**Шаг 2 — Формат**: тип сетки, число участников (степень двойки для elimination: 4/8/16/32/64), Bo1/Bo3/Bo5, 1v1 или командный формат и размер команды.

**Шаг 3 — Деньги**:

- Если `prize_pool_type = FROM_FEES`: организатор указывает `entry_fee`, призовой фонд считается автоматически = `entry_fee × max_participants × (1 - platform_commission_percent)`.
- Если `FIXED_SPONSORED`: организатор указывает фиксированный приз, участие может быть бесплатным или с меньшим взносом.
- Указывается разбивка призовых по местам (валидация: сумма процентов = 100%).

**Шаг 4 — Правила**: текст регламента, требование к пруфу результата (скриншот/видео/оба), правила дисквалификации за читерство.

**Шаг 5 — Публикация**:

- Если организатор `is_verified = true` → статус сразу `REGISTRATION_OPEN`.
- Если не верифицирован → статус `PENDING_MODERATION`, модератор одобряет вручную.

### 4.4 Регистрация участника на турнир

1. Пользователь/капитан команды на странице турнира жмёт "Участвовать".
2. Если `entry_fee > 0`: открывается платёжная форма (Stripe/локальный провайдер) → деньги списываются и переводятся в `EscrowAccount` турнира со статусом `HOLDING`, создаётся `Transaction` типа `ENTRY_FEE_HOLD`.
3. Создаётся `TournamentParticipant` с `payment_status = PAID`.
4. Если участников набралось `max_participants` до дедлайна — регистрация закрывается автоматически (`status = REGISTRATION_CLOSED`).
5. Если к дедлайну набралось меньше минимального порога (настраивается, напр. < 4) — турнир отменяется, всем участникам возвращаются деньги (`Transaction: ENTRY_FEE_REFUND`), статус `CANCELLED`.

### 4.5 Генерация сетки

1. По закрытии регистрации система генерирует `Bracket`/`Match` записи.
2. Посев (seeding): случайный либо по Elo-рейтингу (сильные разводятся по разным половинам сетки).
3. Организатор может вручную скорректировать посев до нажатия "Начать турнир".
4. `Tournament.status = LIVE`, первые матчи получают `status = SCHEDULED`.

### 4.6 Проведение матча

1. Матч переходит в `IN_PROGRESS`, когда наступает `scheduled_at` (или вручную по кнопке "Начать матч").
2. Игроки играют матч в самой игре (EA FC/eFootball) — платформа не хостит геймплей, только фиксирует результат.
3. Каждая сторона вводит счёт + загружает пруф (скриншот/видео) в объектное хранилище (S3/R2).
4. Логика сверки:
   - Если `score_a` от обеих сторон совпадает → `status = COMPLETED`, определяется `winner_id`, победитель автоматически продвигается в `next_match_id`.
   - Если счета не совпадают или одна из сторон не вводит результат за N часов (таймаут, настраивается) → `status = DISPUTED`, создаётся запись `Dispute`.
5. Проигравший выбывает (single elimination) либо уходит в нижнюю сетку (double elimination) либо продолжает участвовать в оставшихся турах (round robin/swiss).

### 4.7 Разрешение спора (Dispute)

1. Модератор видит очередь споров в админ-панели, открывает пруфы обеих сторон.
2. Может запросить дополнительные доказательства (видео повторной записи, встроенная статистика игры).
3. Выносит решение: `RESOLVED_A` / `RESOLVED_B` (кто-то признаётся победителем) либо `REJECTED` (переигровка матча).
4. Match обновляется соответствующим статусом, турнир продолжается.

### 4.8 Завершение турнира и выплаты

1. Когда финальный матч получает `COMPLETED` — `Tournament.status = FINISHED`.
2. Система рассчитывает призовые по `prize_distribution` от общей суммы в `EscrowAccount`.
3. Комиссия платформы (`platform_commission_percent`) списывается отдельной транзакцией `PLATFORM_COMMISSION` на системный счёт.
4. Оставшаяся сумма зачисляется на `Wallet` победителей соответствующих мест (`Transaction: PRIZE_PAYOUT`).
5. `EscrowAccount.status = DISTRIBUTED`.
6. Игроки получают уведомление `PRIZE_RECEIVED`.
7. Elo-рейтинг всех участников пересчитывается по итогам турнира (система рейтинга — например, модификация Elo с учётом занятого места, не только W/L отдельных матчей).

### 4.9 Вывод средств

1. Пользователь в разделе "Кошелёк" видит баланс и историю транзакций.
2. Жмёт "Вывести" → указывает сумму и способ (карта/локальный провайдер) → создаётся `Transaction: WITHDRAWAL` со статусом `PENDING`, отправляется запрос в платёжный провайдер (Stripe Connect payout / аналог).
3. По завершении обработки статус меняется на `COMPLETED` либо `FAILED` (с указанием причины и авто-возвратом на баланс).

### 4.10 Приватные турниры между командами (доп. монетизация)

1. Обычный пользователь (не верифицированный организатор) может создать приватный турнир (`visibility = PRIVATE`) — например, "матч на деньги" между двумя конкретными командами.
2. Такой турнир не отображается в общем листинге, доступен только по прямой ссылке/приглашению.
3. Платформа всё равно берёт комиссию с призового фонда (даже с приватных турниров) — это отдельный источник дохода.

### 4.11 Отмена турнира

1. Организатор может отменить турнир до старта (`status != LIVE`).
2. Всем оплатившим участникам автоматически возвращаются деньги (`ENTRY_FEE_REFUND`).
3. Уведомление `TOURNAMENT_CANCELLED` всем участникам.

## 5. Диаграмма статусов (текстовое описание жизненного цикла)

**Tournament:**
`DRAFT → (PENDING_MODERATION →)? REGISTRATION_OPEN → REGISTRATION_CLOSED → BRACKET_GENERATED → LIVE → FINISHED`
(альтернативная ветка: `→ CANCELLED` на любом этапе до `LIVE`)

**Match:**
`SCHEDULED → IN_PROGRESS → AWAITING_CONFIRMATION → COMPLETED`
(альтернативная ветка: `AWAITING_CONFIRMATION → DISPUTED → COMPLETED` после решения модератора)

**Transaction (для взноса):**
`ENTRY_FEE_HOLD (PENDING → COMPLETED)` → в конце турнира либо `PRIZE_PAYOUT`, либо (если турнир отменён) `ENTRY_FEE_REFUND`

## 8. Технический стек

**Frontend:** Next.js 14+ (App Router), TypeScript, Tailwind CSS, shadcn/ui, Framer Motion, Zustand/React Query, Socket.io-client.

**Backend:** NestJS (TypeScript), PostgreSQL (Prisma ORM), Redis (кэш/очереди/live-статусы), Socket.io/ws сервер, BullMQ для фоновых задач (расчёт призовых, авто-старт матчей по расписанию, отправка уведомлений).

**Инфраструктура:** Docker, GitHub Actions (CI/CD), Sentry (ошибки), Grafana+Prometheus (метрики), Railway/Render/Fly.io для старта, Kubernetes при росте нагрузки.

**Auth:** Auth.js/NextAuth или Clerk, OAuth Discord + Steam.

## 11. Модуль сезонов и дивизионов (режим «Клубы 11 на 11»)

Важное уточнение по продукту: платформа фокусируется **только на режиме «Клубы 11 на 11»** (командный режим EA FC), как и у референса. Весь модуль ниже описывает именно эту механику лиги/сезонов — это то, что отличает продукт от разового турнирного сервиса и превращает его в постоянно живое комьюнити.

### 11.1 Календарь сезонов

Три официальных сезона в год, формирующих командный рейтинг:

| Сезон      | Период            |
| ---------- | ----------------- |
| Осень-зима | октябрь – декабрь |
| Зима-весна | январь – март     |
| Весна-лето | апрель – июнь     |

Летом (июнь–август, между сезонами) — отдельный **развлекательный турнир** (по типу "офсезонного кубка"), где командам разрешено микшировать составы, приглашать гостевых игроков, экспериментировать — рейтинг за него не начисляется.

Каждую неделю (например, по пятницам) — **регулярный еженедельный кубок**, открытый для всех желающих, вне рамок сезона: часть команд использует его для просмотра новых игроков (скаутинг), часть — просто ради игры. Тоже без влияния на официальный рейтинг.

### 11.2 Структура дивизионов

- **Первый сезон платформы**: дивизионов нет — все зарегистрированные команды играют в одной общей группе/сетке. Это точка входа для нового комьюнити.
- **Со второго сезона**: по итогам предыдущего сезона (место в таблице/рейтинг очков) команды распределяются по трём дивизионам:
  - 🥇 **Золотая лига** — топ-команды
  - 🥈 **Серебряная лига** — средний уровень
  - 🥉 **Бронзовая лига** — начальный уровень / новые команды
- **Между сезонами** — система повышения/понижения (promotion/relegation): например, топ-N команд Серебряной лиги поднимаются в Золотую, нижние N команд Золотой лиги опускаются в Серебряную, аналогично между Серебряной и Бронзовой. N настраивается администратором перед каждым сезоном.
- Новые команды, которые не участвовали ни в одном сезоне, стартуют в Бронзовой лиге (или в общей группе, если это всё ещё первый сезон платформы).

### 11.3 Годовой отбор на LAN-турнир

- По результатам всех официальных сезонов года копится **годовой командный рейтинг** (сумма очков/мест за все 3 официальных сезона, с весами — например, более поздние сезоны могут весить больше).
- В конце года лучшие команды по этому годовому рейтингу приглашаются на офлайн **LAN-турнир** с крупным призовым фондом — это "вершина" соревновательной пирамиды платформы и главный мотиватор для игроков на протяжении всего года.
- Нужен отдельный экран/страница "Путь на LAN" с текущим положением команды в годовом зачёте.

### 11.4 Новые сущности данных для этого модуля

  has_divisions (bool — false для первого сезона платформы)

  id, season_id, division_id, promote_top_n, relegate_bottom_n

### 11.5 Флоу: заявка команды на сезон

1. Менеджер (капитан) команды заходит в раздел "Мой клуб" → видит открытую регистрацию на предстоящий сезон (баннер/уведомление на главной странице и в паблике ВК-группы платформы — если есть).
2. Заявляет команду на сезон (создаётся `SeasonTeamEntry`), при необходимости оплачивает орг.взнос сезона (если платформа берёт плату за участие в сезоне, а не только с призовых).
3. Если сезон уже имеет дивизионы — команда автоматически ставится в дивизион по результатам прошлого сезона (или в Бронзу, если новая).
4. Формируется расписание тура (регулярные официальные матчи между всеми командами дивизиона — round robin в течение сезона, не единая elimination-сетка).
5. По окончании сезона — таблица дивизиона (`final_position` для каждой `SeasonTeamEntry`), применяется `PromotionRelegationRule`.

### 11.6 Как стать участником (для игрока, не менеджера)

1. Зарегистрироваться на сайте и **полностью заполнить профиль**: контактные данные, ссылки на соцсети, игровой ник (**геймертег должен точно совпадать** с тем, что указан в самой игре EA FC — иначе команда может получить санкции на официальном матче; нужна отдельная валидация/предупреждение в UI при заполнении профиля).
2. Далее у нового игрока два пути:
   - Уже быть игроком команды, которая участвует в текущем сезоне (тогда игрок автоматически считается участником через `TeamMember`).
   - Стать менеджером и заявить свою команду на сезон (флоу 11.5).
3. Рекомендуемый промежуточный шаг для новичков без команды — сыграть в открытых "сборных" матчах (все желающие собираются вместе через общий чат платформы), чтобы засветиться перед капитанами команд, которые ищут игроков.

## 12. Система рейтинга и статистики игроков (XP / Card Rating)

### 12.1 Ввод статистики матчей

После каждого сыгранного официального матча статистика по каждому игроку (точные передачи, обводки, выигранные единоборства и т.д.) вносится вручную специально назначенными сотрудниками платформы (роль **StatTracker** — расширение роли Moderator) через отдельную админ-форму ввода статистики матча. Обычно данные должны появляться в профиле игрока на следующий день после матча.

### 12.2 Формула XP

- XP — автоматически рассчитываемое значение на основе статистических показателей матча.
- Формула не публикуется пользователям (закрытый расчёт на backend), учитывает как позитивные, так и негативные игровые действия.
- **Формула индивидуальна для каждого игрового амплуа** (вратарь, защитник, полузащитник, нападающий — у каждого разный набор весов статистики, т.к. разные задачи на поле).
- К итоговому XP применяется **множитель дивизиона**: чем выше дивизион (Золотая > Серебряная > Бронзовая), тем выше множитель — это стимулирует бороться за место в топ-лиге.

### 12.3 Пересчёт базового рейтинга карточки игрока

Правила пересчёта в начале нового сезона на основе **суммарного XP за предыдущий завершившийся официальный сезон**:

- Игроки ранжируются по суммарному XP за сезон → место в общем рейтинге определяет новый базовый рейтинг карточки.
- **Минимум 10 сыгранных официальных матчей за сезон**, чтобы попасть в пересчёт.
- Если матчей меньше 10 — рейтинг берётся из последнего сезона, где условие выполнялось, и уменьшается на **2 пункта**.
- Ограничение волатильности: новый базовый рейтинг не может отличаться от рейтинга прошлого зафиксированного сезона **больше чем на 5 пунктов** в любую сторону.

### 12.4 Бонусы к рейтингу в течение сезона

- **Команда тура (TOTW)** — по итогам каждого игрового тура формируется символическая сборная лучших игроков (по позициям). Попадание в TOTW даёт **+1** к текущему рейтингу карточки. Особое правило: если базовый рейтинг игрока ниже 75, первое попадание в TOTW сразу поднимает его до 75 (а не просто +1), последующие попадания добавляют по +1 как обычно.
- **Команда сезона (TOTS)** — по итогам всего сезона формируется символическая сборная сезона, попадание в неё даёт **+3** к рейтингу.

### 12.5 Новые сущности данных

```
PlayerMatchStat
  id, match_id, user_id, position_played,
  pass_accuracy, dribbles, tackles_won, goals, assists,
  other_metrics (JSON — расширяемый набор под конкретную игру),
  xp_earned, entered_by (-> StatTracker user), entered_at

SeasonXpSummary

PlayerRatingHistory

```

- Карточка игрока (аналог FUT-карточки) с текущим рейтингом, амплуа, ключевой статистикой.
- Отдельная страница/вкладка "Статистика" в профиле — по каждому сыгранному официальному матчу.
- Публичный лидерборд игроков по XP за текущий сезон.

### 12.7 Автоматизация ввода статистики через видео (Computer Vision + OCR)

Проблема: игроки после матча присылают видео, где прокручивается статистика каждого участника (стандартный экран режима «Клубы» в EA FC). Ручной ввод этих данных статистами — узкое место и источник опечаток при росте платформы. Ниже — конвейер, который автоматизирует это, адаптированный под уже выбранный backend-стек (Node.js/NestJS + BullMQ + Redis).

**Пайплайн обработки:**

1. **Загрузка видео.** Два источника, оба ведут к одному внутреннему API:
   - через сайт — форма "Загрузить статистику матча" на странице матча, файл сразу уходит в object storage (Cloudflare R2/S3);
   - через Discord-бота — отдельный лёгкий сервис на `discord.js` в специальном канале скачивает присланное видео, кладёт в тот же storage и дёргает internal API `/matches/:id/extract-stats` с URL видео.
   - В обоих случаях создаётся запись `MatchStatExtractionJob` со статусом `QUEUED`.

2. **Обработка — отдельный worker-сервис** (не основной веб-процесс API!), слушающий очередь BullMQ:
   - **Извлечение кадров** — `fluent-ffmpeg` (Node-обёртка над ffmpeg) разбивает видео на кадры, 1–2 кадра в секунду достаточно, чтобы не пропустить прокручиваемую статистику.
   - **Обрезка зон интереса (ROI)** — через `sharp` вырезаются фиксированные прямоугольники координат: интерфейс EA FC стандартизирован, поэтому координаты зоны "список игроков" (для определения, кто сейчас выделен/активен) и зоны "значения статистики" известны заранее (нужен конфиг координат под каждое типовое разрешение видео — 1920×1080, 1280×720 и т.д., т.к. игроки присылают видео в разном разрешении).
   - **Предобработка кадра** — приведение к чёрно-белому, увеличение контраста (тоже через `sharp`) для повышения точности OCR.
   - **Распознавание текста (OCR)**:
     - MVP-вариант — `tesseract.js` (open-source, бесплатно, работает прямо в Node);
     - продакшн-вариант с высокой точностью, особенно для кириллицы — облачный API (`@google-cloud/vision` или Yandex Vision), платный за объём.
     - Рекомендуемая стратегия: начать с Tesseract.js, а для кадров с низким confidence score распознавания — автоматически пересылать их в облачный API как fallback (гибрид: дёшево на основной массе, точно на сложных случаях).
   - **Сборка и дедупликация** — по последовательности кадров скрипт определяет, какой игрок сейчас выделен в списке слева, собирает пары "метрика → значение" из правой зоны, игнорирует уже собранные повторяющиеся значения (статистика видна на нескольких соседних кадрах, пока прокрутка на одном игроке). При смене выделенного игрока — сохраняет собранный JSON предыдущего игрока и начинает собирать для следующего.
   - Итог этапа — структурированный JSON статистики по каждому игроку матча.

3. **Сопоставление с игроками.** Распознанный никнейм сверяется с `GamertagHistory`/текущими геймертегами именно тех игроков, что заявлены на этот матч (через `TournamentParticipant`/состав команд), а не со всей базой пользователей — это резко снижает риск ложных совпадений. Дополнительно — fuzzy-matching (например, расстояние Левенштейна) на случай, если OCR ошибся в 1–2 символах ника.

4. **Обязательная верификация перед публикацией** (критично для доверия к системе — полностью автоматическая публикация без проверки недопустима):
   - Распознанные данные не попадают в профиль игрока сразу — job переходит в статус `AWAITING_REVIEW`.
   - StatTracker в админке видит таблицу: распознанные значения + confidence score OCR + оригинальный кадр рядом для визуальной сверки.
   - Модератор одним кликом подтверждает всю пачку целиком либо точечно правит отдельные неверно распознанные значения — это на порядок быстрее, чем вводить всё вручную с нуля.
   - После подтверждения создаются записи `PlayerMatchStat`, запускается пересчёт XP (раздел 12.2).

5. **Самообучение со временем (после MVP, опционально).** Каждое ручное исправление модератора — готовая пара "распознано автоматически / верное значение". Накопленный датасет можно использовать для дообучения собственной OCR-модели под конкретный шрифт интерфейса EA FC, постепенно снижая долю ручных правок.

**Новые сущности данных:**

```
MatchStatExtractionJob
  id, match_id, source (WEB_UPLOAD / DISCORD_BOT), video_url,
  status (QUEUED / PROCESSING / AWAITING_REVIEW / APPROVED / FAILED),
  raw_extracted_json (JSON — сырые данные по каждому игроку),
  overall_confidence_score, processed_at, reviewed_by (-> StatTracker), reviewed_at

ExtractionFrameSample  (опционально, для отладки и накопления датасета под 12.7.5)
  id, job_id, frame_timestamp_ms, roi_type (PLAYER_LIST / STAT_VALUE),
  cropped_image_url, ocr_raw_text, ocr_confidence
```

**Технические заметки:**

- Обработку видео нельзя гонять в основном процессе NestJS API — обязателен отдельный worker-процесс (можно в том же проекте, но отдельная точка входа, слушающая BullMQ-очередь), иначе тяжёлая обработка положит основной API под нагрузкой.
- Ключевые библиотеки: `fluent-ffmpeg`, `sharp`, `tesseract.js`, опционально `@google-cloud/vision`.
- Этот пайплайн **не заменяет**, а дополняет ручной ввод StatTracker'ом (раздел 12.1) — ручной ввод остаётся резервным способом на случай сбоя распознавания или для турниров, где видео не прислали.

## 13. Клубы, трансферы и контракты

### 13.1 Создание клуба

Отдельная страница/форма «Создать клуб» со следующими полями и блоками:

**Основные данные:**

- Название клуба (обязательное)
- Сокращение (короткий тег клуба, обязательное — используется в таблицах, сетках, где мало места)
- Страна (выпадающий список)
- Группа во ВКонтакте (URL, опционально)
- Канал на Twitch (URL, опционально)
- Канал на YouTube (URL, опционально)

**Цветовая схема клуба:**

- Основной цвет — выбор из палитры свотчей (заготовленный набор ~10-12 цветов)
- Второй цвет — аналогичный выбор из палитры
- Акцентный цвет — «необязательный цвет для воротника, номеров и акцентов» — тоже выбор из палитры

**Шаблон формы (генератор игровой футболки):**

- Галерея из 8 готовых шаблонов дизайна формы (например: классический, вертикальные полосы, полоса на груди, диагональ, контрастные рукава, центральная полоса, половинки, геометрический узор)
- Live-превью выбранной формы тут же перерисовывается в цветах, выбранных выше (основной/второй/акцентный) — это SVG- или Canvas-генератор, а не загрузка готовой картинки
- Подпись под превью: «Так форма будет выглядеть в сборной тура и других клубных блоках» — то есть эта сгенерированная форма переиспользуется как визуальный идентификатор клуба в других местах платформы (например, иконка в TOTW/TOTS)

**Персонализация (шапка страницы клуба):**

- Превью «как на странице клуба» — широкий баннер-шапка (аналог cover-фото), можно загрузить свою картинку
- Рекомендации по размеру: ориентировочно 1890×320 px (соотношение сторон примерно 189:32), максимальный размер файла — до 1 МБ
- Кнопка "Выберите изображение" / "Загрузить обложку"

**Сохранение:**

- Кнопка "Сохранить" создаёт клуб; создатель автоматически становится менеджером/капитаном (`TeamMember.role = captain`).
- Логотип клуба отдельно от баннера — **рекомендуется формат PNG без прозрачного фона** (нужна валидация на фронте/бэке — проверка альфа-канала при загрузке), т.к. логотип используется как маленькая иконка на разноцветных фонах по всему сайту (таблицы, сетки турниров, карточки матчей).

### 13.1.1 Дополнительные сущности данных для формы создания клуба

```
Club (расширение сущности Team из раздела 3)
  ...существующие поля Team...
  abbreviation, country, vk_group_url, twitch_url, youtube_url,
  primary_color (hex), secondary_color (hex), accent_color (hex, nullable),
  kit_template_id (-> KitTemplate), cover_banner_url

KitTemplate
  id, name (напр. "Классический", "Вертикальные полосы", "Полоса на груди",
       "Диагональ", "Контрастные рукава", "Центральная полоса",
       "Половинки", "Геометрический узор"),
  render_type (SVG_LAYERED / CANVAS_GENERATED),
  template_asset_url  (базовый SVG/шаблон, куда программно подставляются
       primary_color / secondary_color / accent_color клуба)
```

Технически генератор формы проще всего реализовать как набор SVG-файлов с именованными `<path>`-слоями (например `body-primary`, `sleeves-secondary`, `collar-accent`), где цвет каждого слоя задаётся через CSS `fill` на основе `primary_color`/`secondary_color`/`accent_color` клуба — тогда превью перекрашивается мгновенно на фронтенде без бэкенд-рендеринга картинки.

### 13.2 Раздел "Трансферы"

Два подраздела:

- **Игроки ищут команду** — игрок публикует объявление: амплуа, игровые дни/время, короткое "о себе". (`PlayerTransferAd`)
- **Клубы ищут игроков** — капитан публикует открытую вакансию клуба: нужное амплуа, требования, условия. (`ClubTransferAd`)

Игроки и капитаны находят друг друга через эти списки и связываются напрямую (через контакты в профиле или встроенный чат/сообщения, если будет реализован).

### 13.3 Контракты

- Капитан отправляет игроку предложение контракта через "Мой клуб": срок действия (**максимум 3 месяца**), сумма отступных (buyout fee) за досрочный уход.
- Игрок получает список предложенных контрактов в своём кабинете и принимает/отклоняет.
- **Если у контракта указан срок действия — игрок не может самостоятельно покинуть клуб до его истечения без согласия капитана** (либо выплатив отступные, если такая опция предусмотрена).
- По истечении срока контракт автоматически становится "открытым" (free agent), либо продлевается, если обе стороны подтвердили продление.

### 13.4 Новые сущности данных

```
PlayerTransferAd
  id, user_id, position, available_days (JSON), about_text,
  status (ACTIVE / CLOSED), created_at

ClubTransferAd
  id, team_id, position_needed, requirements_text,
  status (ACTIVE / CLOSED), created_at

Contract
  id, team_id, user_id, offered_by (-> captain User),
  duration_months (max 3), buyout_fee,
  status (PENDING / ACCEPTED / DECLINED / ACTIVE / EXPIRED / TERMINATED),
  start_date, end_date, created_at
```

## 15. Детальная спецификация страницы профиля игрока

Профиль игрока — один из самых насыщенных экранов платформы, состоит из 4 вкладок.

### 15.1 Вкладка «Профиль»

- **Карточка игрока** (виджет в стиле FUT-карточки): крупный рейтинг + сокращение амплуа сверху, фото/аватар, ник игрока, набор из 6 характеристик (аналог атаки/паса/дриблинга/созидания/обороны/единоборств — можно адаптировать под свой набор метрик), флаг страны, логотип текущего клуба. Кнопки: "Как считается рейтинг" (ссылка на FAQ), "Скачать" (карточку как картинку — полезно для игроков, чтобы делиться в соцсетях).
- **Блок личных данных**: дата регистрации на платформе, игровой ник (должен совпадать с ником в самой игре — см. 11.6), ФИО (опционально), страна, город, дата рождения/возраст, статус подписки (если будет премиум), основное амплуа, дополнительные амплуа, иконки-ссылки на соцсети игрока.
- **Блок «Условия контракта»**: текущий клуб, статус игрока (игрок / капитан / менеджер), дата окончания контракта (или "бессрочно"), сумма отступных, кнопка "Подробная информация" → модалка/страница с полной историей контракта.
- **Блок «Избранные награды»** — игрок может закрепить несколько наград из своей коллекции трофеев на видном месте профиля (пустое состояние: "Нет избранных наград").
- **Блок «Общая статистика»** — агрегированные показатели за всё время на платформе: всего сыграно матчей, всего заработано XP, средний рейтинг, голы, голевые передачи, точность передач (%), успешные отборы, перехваты, сухие матчи (для вратарей). У каждой метрики — глобальный ранк игрока среди всех пользователей платформы (например "#1344"), что создаёт соревновательный элемент и мотивацию улучшать статистику.
- **Блок «Любимые позиции»** — горизонтальные полоски с процентом времени, проведённого на каждой позиции (вратарь / центр. защ. / фланг. защ. / опорн. полузащ. / центр. полузащ. / фланг. полузащ. / атак. полузащ. / нападающий).
- **Блок «Позиционный рейтинг»** — визуализация футбольного поля с расстановкой игрока по позициям, где он играл; на каждой позиции отображается средний рейтинг именно за матчи на ней (например, ЦЗ 7.25, ЛЗ 7.19 и т.д.) — наглядно показывает, где игрок сильнее всего.
- **История смены геймертега** — список всех прошлых игровых ников с датами действия (важно для модерации/детекта смены личности и споров).

### 15.2 Вкладка «Статистика»

Три под-вкладки:

- **Турнирная** — построчно статистика по каждому турниру/сезону, в котором участвовал игрок.
- **Клубная** — статистика в разрезе клубов, за которые он выступал.
- **В матчах** — статистика по каждому отдельно сыгранному матчу.

Фильтры над таблицей:

- **По амплуа** — просмотр статистики только за матчи на конкретной позиции (Все / ЦАП / КЗ / К3 / ФЛ / КП и т.п. — набор сокращений своих позиций).
- **По категории метрик** — переключатель: Общая сводка / Удары / Пасы / Перемещение / Отбор мяча / Выбор позиции / Удержание мяча / Другие / Вратарские (отдельный набор метрик для голкиперов).

Столбцы таблицы (турнирная вкладка): название турнира/сезона (ссылка + иконка лиги), заработано XP, средний рейтинг за турнир, сыграно матчей, голы, голевые передачи, гол+пас суммарно, показатель импакта на результат (+/-), сейвы (вратари), перехваты, % побед, % выигранных единоборств.

### 15.3 Вкладка «Переходы»

Таблица истории трансферов игрока между клубами: клуб (с логотипом), количество матчей, сыгранных в составе клуба, средний рейтинг за этот период, оценка капитана в звёздах (если реализована такая механика), сколько дней провёл в клубе, период пребывания (дата входа → дата ухода, с визуальными стрелками "вошёл"/"вышел").

### 15.4 Вкладка «Трофеи»

Фильтр по категориям наград:

- Все награды
- Командные достижения (медали за результаты команды — золото/серебро/бронза лиги, кубков)
- Индивидуальные достижения (личные награды — MVP тура, лучший бомбардир и т.п.)
- Руководство (награды за менеджерскую/капитанскую деятельность)
- Еженедельный кубок (награды за результаты в регулярном пятничном турнире)
- Символические клубы (за попадания в TOTW/TOTS)
- Особые (уникальные разовые/праздничные награды)

Каждая награда отображается карточкой: иконка, название, короткое описание условия получения, ссылка "Подробнее" (модалка с деталями — когда и за что именно получена).

## 16. Важное юридическое примечание

Приём платежей за участие в турнирах с призовым фондом регулируется в разных странах по-разному (законы об азартных играх могут применяться в зависимости от того, считается ли результат skill-based или game-of-chance). Перед реальным запуском с реальными деньгами — обязательна консультация с юристом в юрисдикциях, где планируется работать. Этот документ не является юридической консультацией.
